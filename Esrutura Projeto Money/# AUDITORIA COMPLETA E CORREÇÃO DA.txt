# 1. REGRA FINANCEIRA OFICIAL DO SISTEMA

Esta regra é obrigatória e deve ser tratada como regra central do domínio financeiro.

## 1.1 CONTAS A PAGAR / DESPESAS

Toda despesa deve ser classificada financeiramente pela:

**DATA DE VENCIMENTO**

Campos:

```text
data                 = data do lançamento/compra
data_vencimento      = data de competência financeira da despesa
pago                 = indica se foi efetivamente paga
data_pagamento       = data em que foi efetivamente paga
```

Exemplo:

```text
Compra:              20/07/2026
Vencimento:          10/08/2026
Pagamento:           08/08/2026
```

Essa despesa pertence à competência:

```text
AGOSTO/2026
```

e nunca a julho.

Outro exemplo:

```text
Compra:              20/07/2026
Vencimento:          10/08/2026
Pagamento:           15/08/2026
```

Continua pertencendo à competência:

```text
AGOSTO/2026
```

A data de pagamento NÃO deve alterar a competência da despesa.

---

# 2. REGRA PARA RECEITAS

Toda receita realizada deve ser classificada financeiramente pela:

**DATA DE RECEBIMENTO**

Campos:

```text
data                 = data do lançamento/origem da receita
data_pagamento       = data em que a receita foi efetivamente recebida
pago                 = 1 somente quando efetivamente recebida
```

Exemplo:

```text
Lançamento:          25/07/2026
Recebimento:         05/08/2026
```

A receita pertence à competência:

```text
AGOSTO/2026
```

e não julho.

Portanto:

```text
RECEITAS REALIZADAS
→ pago = 1
→ data financeira = data_pagamento
```

Receita ainda não recebida:

```text
pago = 0
data_pagamento = NULL
```

não deve ser contabilizada como receita realizada.

---

# 3. REGRA RESUMIDA DE COMPETÊNCIA

Crie internamente uma regra conceitual única:

```text
Despesa:
    DataFinanceira = COALESCE(data_vencimento, data)

Receita:
    DataFinanceira = data_pagamento
```

Nunca use simplesmente:

```text
t.data
```

para calcular receitas realizadas.

Nunca use:

```text
t.data
```

como competência de uma despesa quando existir `data_vencimento`.

# 42. CRITÉRIO FINAL DE ACEITAÇÃO

O sistema somente poderá ser considerado corrigido se esta regra for verdadeira em TODO o aplicativo:

```text
┌──────────────────────────────────────────────┐
│ DESPESAS / CONTAS A PAGAR                    │
│                                              │
│ Competência = DATA DE VENCIMENTO             │
│                                              │
│ Não importa quando foi paga.                 │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│ RECEITAS                                     │
│                                              │
│ Competência = DATA DE RECEBIMENTO            │
│                                              │
│ Somente entra como realizada quando recebida.│
└──────────────────────────────────────────────┘
```

Nenhuma tela, View, relatório, gráfico, Dashboard ou serviço poderá utilizar outra regra.

Antes de concluir, procure novamente no código por:

```text
t.data
data>=
data<
strftime('%m',t.data
strftime('%Y',t.data
strftime('%Y-%m',t.data
```

e analise cada ocorrência para garantir que ela não esteja violando as regras acima.

Também procure por:

```text
data_vencimento
data_pagamento
pago
```

e confirme que cada uso possui semântica correta.

Não considere a tarefa concluída até que todo o projeto esteja consistente com essas regras.
